# Story AI 정책 구현·비교 기록

작성일: 2026-09-29. 정책 구현 범위는 일반 `FIXED`, 엘리트 `ADAPTIVE`, 보스 `BOSS`다. 세 정책은 동일한 `PlacementSearch`와 `BoardEvaluator`를 사용한다. 설정의 탐색 상태 수·시간 예산·행동 간격은 그대로이며 정책이 평가 가중치만 선택한다.

## 검증 결과

JDK 8로 AI·Core·Controller와 연관 테스트를 별도 출력 디렉터리에 컴파일해, `AIControllerTest`, `HeuristicStrategyTest`, `PlacementLogTest`, `MonsterStrategiesTest`, `WeightPoliciesTest`를 `-ea -Djava.awt.headless=true`로 실행했다. 5개 모두 통과했다. 검증 항목은 실제 엔진 입력의 합법성, 잘못된 정책 결과의 복구, 관측 사본 고정, 관측 6회 경계, 수락한 이전 가중치만으로 이동, 경기 ID 격리, 보스 HP 2/3·1/3 경계, 회복 시 국면 유지, 허용 가중치 범위다.

`MonsterBalanceBenchmark --compare`도 같은 JDK 8·headless 환경에서 실행했다. 비교 쌍은 같은 Stage·몬스터 HP·시드·프로필 기본 가중치·행동 간격·탐색 상태/시간 한도를 사용한다. 각 쌍의 한쪽은 고정 가중치, 다른 쪽은 실제 설정 정책을 적용했다. 2개 Stage × 2등급 × 2시드 × 2정책의 16회 실행 결과:

| 등급 | 고정 기준 몬스터 승/4 | 설정 정책 몬스터 승/4 | 미해결 경기 | 정책 복구 |
|---|---:|---:|---:|---:|
| 엘리트 | 3 | 3 | 0 | 0 |
| 보스 | 4 | 4 | 0 | 0 |

이 샘플에서 승패·배치 수·착지 후보 수는 쌍별로 같았다. 따라서 정책 연결과 경계 동작은 검증됐지만, **실제 난이도 개선은 입증되지 않았다**. 엘리트 경기에서는 고정 기준과 설정 정책 양쪽에 탐색 시간 초과가 기록되었고, 측정한 계획 시간도 실행 순서에 따라 달랐다. 시간 예산을 사용하는 현재 탐색은 동일 시드만으로 완전한 결과 재현을 보장하지 않는다. 고정 기준과 새 정책이 같은 착지를 골랐다는 사실도 다른 보드·플레이어 성향에서 같은 행동을 보장하지 않는다.

다음 밸런스 결정에는 실제 플레이어의 여러 경기, 난이도별 승률·경기 시간·행동 경로, 탐색 시간 초과와 실패 복구 횟수가 필요하다. 이 합성 비교는 사람의 체감 난이도 근거로 사용하지 않는다.

## 실행 방법과 조절 위치

프로젝트 통합 빌드의 테스트 컴파일 뒤, 테스트 클래스 경로에서 `kr.ac.jbnu.se.tetris.app.MonsterBalanceBenchmark --compare-smoke` 또는 `--compare`를 실행한다. `--compare-smoke`는 첫 Stage의 엘리트 한 시드만 실행해 설정·런타임 연결을 확인한다. 자동 테스트 묶음에는 포함되지 않는 수동 비교 도구다.

조절값은 `src/main/resources/ai/profiles.properties`에 있다. `maxWeightDeltaRatio`를 올리면 엘리트·보스의 기본 가중치 대비 이동 폭이 커진다. `delayMillis`를 올리면 몬스터 행동 간격이 늘어난다. `maxSearchStates`와 `budgetMillis`를 올리면 더 넓은 탐색이 가능하나 CPU 시간도 늘 수 있다. 엘리트 관측 최소 6회·이전 수락 가중치로의 이동 속도, 보스의 HP 경계·국면별 비율은 각 정책 클래스의 상수와 계산식에서 조절한다. 수치 변경 뒤에는 정책 경계 테스트, 실제 입력 경로 회귀, 동일 조건 비교를 다시 수행한다.
